# 折弯机上模下模扩充工作流

本流程用于扩充 Nearblade 折弯机模具系列，覆盖分类核对、豆包调研、Alibaba 产品与图片采集、页面完善和验收。先复用已有页面，再补充有明确差异的新类型；既有产品 ID、URL 和已确认资源继续保留。

分类、产品和页面关系统一维护在 `content/catalog/products.json`。本文件中的页面清单是开始本轮工作时的核对记录，后续执行时须重新读取实际目录，不能把本文件当作第二份产品数据库。十个正式一级系列保持不变，所有新增模具仍归入 `press-brake-tooling`。

本流程沿用[产品图片工作流](../product-imagery/WORKFLOW.md)、[手册分类核对](manual-taxonomy-audit.md)和根目录 [AGENTS.md](../../AGENTS.md)。下列基线按用户要求建立于 2026 年 10 月 31 日的本地工作区，包含尚未提交的页面优化；不据此推定线上版本已经更新。

## 开工前核对已有页面

每批工作先检查 `git status --short`，读取目录、`tooling-details.json`、SEO 配置和既有素材记录。保留工作区已有修改，核对旧页面覆盖的工艺后，再确定新增范围。

当前共 1 个总览页、7 个模具子页、1 个快夹附件页，没有独立的标准单V、双V或多V下模页。

| 现有 ID | 页面范围和 URL | 本轮处理 |
| --- | --- | --- |
| `pb-001` | 模具总览，`/products/pb-001` | 继续作为系列入口，整理上模、下模、专用成形和附件导航 |
| `pb-straight-punch` | 直身上模，`/products/pb-straight-punch` | 完善现页，不另建“标准直刀”同义页 |
| `pb-gooseneck-punch` | 鹅颈上模，`/products/pb-gooseneck-punch` | 大弯、小弯和避位轮廓先放入此页核对；有独立工艺与资料后再评估拆分 |
| `pb-radius-tooling` | R形及半径折弯工具，`/products/pb-radius-tooling` | 补清上模、圆柱工作部、镶件和下模配套关系；不因“R圆刀”名称另建重复页 |
| `pb-u-forming` | U形成形工具，`/products/pb-u-forming` | 继续解释配套结构、分步或一次成形及脱模；不直接复制为“U形下模”页 |
| `pb-embossing` | 定制截面成形工具，`/products/pb-embossing` | 保留历史 ID；当前名称为 Custom Profile Forming Tooling，不把路径中的 embossing 当作已确认的文字压印能力 |
| `pb-container` | 集装箱成形工具，`/products/pb-container` | 保留行业应用页，关联实际使用的工具；不替代标准上模或下模分类 |
| `pb-light-pole` | 灯杆折弯工具，`/products/pb-light-pole` | 保留行业应用页，按工件截面、锥度和工序完善 |
| `pb-quick-clamps` | 上模快夹，`/products/pb-quick-clamps` | 继续归入附件，核对接口；不计入模具刀型数量 |

已有图库中，直身上模、鹅颈上模和快夹各接入一张白底图；半径、U形、定制截面、集装箱和灯杆子页使用尺寸说明模式，尚无白底照片图库。它们已有独立 Hero，不代表照片采集或实际页面视觉验收已经完成。具体资源以目录和[模具素材记录](../product-imagery/tooling-rebuild/media-audit.json)为准。

## 建页前处理重复和范围重叠

对每个候选类型，比较名称与同义词、上下模角色、工作截面、成形任务、配套关系和安装接口，记录“复用现页、补充选项、新建候选页、关联成套工具”中的处理方式。

| 候选范围 | 处理原则 |
| --- | --- |
| 直刀、标准上模 | 复用 `pb-straight-punch`；角度、刀尖R和长度作为规格 |
| 尖刀、锐角上模 | 核对与现有直身上模的用途和截面差异；资料支持时新建候选页，30°作为规格而非唯一产品定义 |
| 鹅颈、大小弯刀、避位刀 | 优先完善 `pb-gooseneck-punch`，以喉深、截面和干涉空间区分，避免同义词各建一页 |
| R圆刀、圆柱工作部、半径工具 | 优先完善 `pb-radius-tooling`；整体式与镶件式分别核对，不能未经图纸合并其结构 |
| 单V、双V、多V、可调V下模 | 分别建立资料卡；核对固定槽数与开口可调机构的区别，再决定独立页面 |
| 滚轮、翻转翼或摆块、聚氨酯软模 | 分别核对机构和接触方式，不以“无压痕”一个名称代替全部类型 |
| 压死边上模、下模 | 先建立同一成套工艺资料卡；只有存在明确独立部件需求和专属资料时，才拆部件页并互相关联 |
| 段差上模、下模 | 先核对同一Z形成形方案的上下模配对，避免把同一套工具重复统计为两个完整方案 |
| R形下模、U槽下模 | 先与已有半径页、U形成形页对照；确认具体部件与接口后决定完善原页或增加部件页 |
| 压筋、压印、其他截面成形 | 先与 `pb-embossing` 对照；该页保留为定制截面入口，不自动宣称所有特殊工艺均可供货 |

独立页面需要有区别于现页的采购任务、对应截面或部件、尺寸与接口要求、配套关系以及可用素材。仅有新名称、新角度、不同长度或一张新图片时，先完善原页的规格与选项。

新 ID 在确认范围后按现有命名方式确定，先搜索全站目录、SEO、文章关联和历史跳转，再写入唯一目录。研究记录中的暂定 ID 不代表已建页。既有 URL 默认保留；确需归并时，记录原地址、目标地址及原因，并同步历史跳转、内链和 sitemap，不静默删除或改变旧地址的产品含义。

## 分批执行顺序

| 批次 | 范围 | 完成条件 |
| --- | --- | --- |
| 第一批 | 完善现有直身上模；调研尖刀、单V和双V下模 | 四类资料卡、重复核对、来源比较和相应本地页面形成完整样例 |
| 第二批 | 完善鹅颈及大小弯轮廓；补多V和可调V下模 | 上模避让与下模结构有对应图示，型号和接口边界清楚 |
| 第三批 | 压死边、段差及减压痕方案 | 上下模、工件和成形步骤对应；滚轮、摆块和软模分别核实 |
| 后续完善 | 现有半径、U形、定制截面及行业专用页 | 补齐各页照片、结构说明和采购字段，消除与新增条目的重复 |

每批完成资料和本地验收后再扩下一批；单个候选缺资料时记录缺口，继续处理不依赖该资料的类型。

## 豆包调研和来源核对

使用用户已经打开的豆包正式浏览器窗口，一次研究一个类型。先记录当前对话和已有结论，保留用户内容；使用结构化追问补齐信息。可采用下面的提问模板：

> 请检索折弯机的【类型名称】，给出中文常用名称和英文采购关键词、结构与截面特征、常见混淆类型、成形工序、配套上模或下模、关键尺寸及安装接口、询价需要的信息。提供可打开的原始来源链接，并指出哪些是厂家专有方案。另找整体产品图、端面截面图、接口近照和成形示意的来源页面；说明图片是否为实物照片、工程图或示意图。无法核实的信息请明确列出。

打开豆包给出的链接核对原文和图片。技术定义优先用原厂或刀具厂商目录交叉验证；豆包回答、搜索摘要和商品标题保留为线索，不直接作为本厂规格或产能依据。

材料、热处理、硬度、允许线载荷、角度和板厚范围都要核对其对象与条件。接口名称须落实到刀柄、承载肩、底座和锁紧结构；不按机器品牌笼统判断兼容或不兼容。

## Alibaba 产品比较和图片采集

使用用户已登录的正式浏览器，按中文同义词和英文采购词正常搜索。每类以五家不同店铺作为首轮比较目标；同一店铺的多个商品算一家。已有比较记录可以沿用，但须确认它覆盖本次具体类型和当前来源页面。

每家记录店铺、商品页、实际产品类型、截面与接口、照片和工程图链接、规格声明及采用或淘汰原因。标题与图片不一致时，以可核实的实际部件为准并标记差异。只记录浏览器和文件中确认的内容，不把未打开的详情页写成已核验。

每类优先采集整体图、端面图、安装接口近照和上下模配合或工件示意。图片先完成下载，再检查实际格式、像素、压缩细节和水印。优先选择原本无品牌和水印的自然产品图；使用状态与授权情况内部记录。

原图和处理版本分开保存。白底图库与深蓝 Hero 使用独立资源，尺寸与编辑要求沿用[产品图片工作流](../product-imagery/WORKFLOW.md)。需要图片编辑时读取并遵守当前 imagegen 技能，逐张检查截面、V槽、刀尖R、刀柄和保持结构，记录实际输出尺寸。图片缺口单独记录为待补图；对应工程示意放在下方尺寸区，不能代替介绍区实物图，不将工程图或生成图认作产品实拍。

登录、验证码等需要用户操作时保留现场。浏览器连接失败或检测到用户切换页面时，先读取最新状态；短超时重试一次仍失败，就记录阻塞并推进独立资料或本地工作。完整网页下载挂起时改为单图下载。操作超时、按钮点击和下载开始均不算采集完成。

## 页面接入

1. 在 `content/catalog/products.json` 中更新现页或加入已核实的新条目，沿用 `pb-001` 系列关系。已有成套模具页可以从上模和下模选型路径关联，同一 URL 不复制成两个产品。
2. 分别维护功能条目、角度等规格、设备接口和附件。沿用当前 `variantGroups` 的属性展示及 `productGroups` 的子页导航；每个已有子页在目录中保留明确入口，不为了展示同一产品的多个用途而重复建记录。
3. 为每个 ID 补全 `content/catalog/tooling-details.json` 的角色、工艺、尺寸、接口、检验说明及对应轮廓。新增轮廓时同步绘图组件、类型定义和生成脚本，核对其展示的是上模、下模还是成套工具。
4. 总览 `pb-001` 的指南继续核对 `src/data/productGuides.ts`。页面维持现有 Hero、白底图库、尺寸说明及本页询价路径；仅在本类素材通过检查后替换对应图片，不覆盖其他类型的资源。
5. 同步 `content/seo/pages.json`、九种语言、列表与系列导航、相关产品和文章引用。保留原 URL 的规范地址，不因改名生成重复索引页面。

现有测试中包含产品总数、子页数量、轮廓数量等基线。确实新增产品后，按最终范围更新这些断言，同时保留十个系列顺序、旧页兼容、图片存在、独立指南及翻译完整性检查，不能删除检查以通过构建。

## 验证和交付

完成页面内容后提取英文键，补齐其余八种语言，再运行完整检查：

```sh
npm run i18n:extract
# 补齐 content/locales/ 中的译文后再执行以下命令
npm test
git diff --check
npm run preview
```

自动检查确认现有 ID 和 URL 保留、新页无重复、子页归属正确、SEO与初始 HTML 正文一致、语言包完整、历史跳转有效、所有图片存在且内部制作记录未进入公开内容。实际预览端口以服务输出为准。

在实际产品页分别检查桌面与手机的 Hero 裁切和文字、全部图库与缩略图、放大与关闭、尺寸图、分类导航及本页询价定位。对照旧页面检查新分类没有覆盖原内容或造成关联失效。样例页、自动测试和其他页面使用相同组件均不能替代本页视觉验收。

交付记录包括本批修改与新增 URL、来源和图片记录、测试结果、实际检查范围、未解决事项及本地链接。资料采集、页面接入、自动检查、实际验收、提交和部署分别记录，不能相互推定。

本轮默认本地调研、编辑与预览；提交、推送和部署按用户后续明确授权执行。既有部署成功和旧批次授权不代表本轮已发布或获得持续发布授权。

## 2026-11-01 用户修订：以鹅颈页作为介绍区标准

用户指出介绍页面的预览大图应使用网上核实的实物图，尺寸规格图放到下面，指定 `/products/pb-gooseneck-punch` 为标准。此要求优先于此前“缺图时把工程图移到介绍区”的临时方案。

- 介绍区使用对应类型的白底实物照片，支持放大；图库中不混尺寸图、CAD渲染或深蓝Hero。工程尺寸图在下方“尺寸与配合”区独立展示，不能顶替介绍区大图。
- 接入时同时更新目录主图和 `images`，移除本批已补照片产品的 `mediaMode: specification`，复用鹅颈页现有照片布局及下方指南。保留既有URL和独立Hero。
- 照片与工程示意逐项核对槽数、所在面、工作刃和安装结构。双V不能用翻面槽示意去对应同面双槽照片；多V不能将三槽照片写成四槽或八槽标准配置。示意图仍不是供货图纸。
- 没有合格实物图的页面保持待补图状态，不用生成实物或工程图代替并宣称完成。低于像素目标的候选必须明确记录缺口；AI编辑输出更大不等于获得更高原生分辨率。
- 验收检查介绍区真实照片、下方尺寸图的DOM顺序、桌面/手机实际页面与放大。自动检查应防止本批页面退回顶部规格图模式；人工视觉检查另行记录。

本批直身、尖刀、单V、双V、多V的来源、原生像素、图片编辑提示词与待验收项见 [介绍区照片记录](../product-imagery/press-brake-intro-photos-2026-11-01.json)。半径、U形、定制截面、集装箱和灯杆的既有照片缺口仍需继续采集，不在本批五页修正中冒称已补齐。
