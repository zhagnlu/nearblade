# Nearblade SEO 执行工作流

更新日期：2026 年 10 月 30 日。

目标是让有实际采购需求的客户找到合适的工业刀片或折弯模具，理解选型与图纸要求，并发起有效询价。先完善英文商业页面和采购指南，再依据搜索与询盘数据扩展主题及语言。

## 当前基础

网站有十个正式产品系列、30 个产品详情页、3 篇文章，共 39 个公开页面。唯一目录为 `content/catalog/products.json`，页面搜索意图、关键词、标题和描述维护在 `content/seo/pages.json`。

当前工作区正在实现完整英文正文预渲染和 React hydration 接管。构建结果不等于线上已更新；本轮尚未确认线上版本、GSC 收录与性能数据。九种语言包用于界面翻译，当前 canonical 和初始元数据仍对应英文页面。

询价表单通过 `mailto:` 打开客户的邮件草稿。草稿打开、邮件链接点击与实际收到询盘分别记录，不能混为转化数量。

2026 年 10 月 30 日本地复核：`npm test` 完成构建及 29 项测试，全部通过；覆盖静态正文、元数据、产品入链、hydration、部分图库和语言交互及接管前输入保留。桌面和手机视觉验收、线上版本确认仍待完成。首页数字测试只确认静态输出与现有配置一致，不构成对宣传能力的核实。

## 执行顺序

### 建立线上和数据基线

1. 核对正式域名及跳转、产品页 HTTP 状态、初始 HTML 正文、未知路径的 404、robots、sitemap、canonical 和退役产品地址。
2. 检查桌面和手机实际页面，覆盖首次加载、导航、语言恢复、图库、放大及询价输入。
3. 使用本站 GSC 数据，记录 property、搜索类型、提取时间、数据截止日期与筛选条件。比较完整且等长的 7 天和 28 天周期；分析查询词、落地页、国家和设备，站点总数与明细表分开。
4. 分辨未收录、曝光减少、位置变化和 CTR 下降。没有 GSC 时可推进已有证据支持的修复，并标明选题假设，不虚构搜索量和排名原因。
5. 核实首页、About 和 Equipment 的宣传依据，包括 ±0.001 mm 能力、15 年经验、认证、行业覆盖及设备归属。尚未找到依据不等于已经证实错误；具体能力须对应产品、工艺、检验条件和资料。

### 完善商业页面和采购路径

保留十个正式系列及既有产品 ID，遵循[手册分类核对](catalog/manual-taxonomy-audit.md)。不因外形、图片或关键词重新划分类目，不仅为关键词新增重复分类页。

| 页面类型 | 主要任务 | 应连接的页面 |
| --- | --- | --- |
| 首页与产品总目录 | 说明供货范围，帮助进入正确系列 | 系列页、企业证据、询价入口 |
| 系列页 | 比较类型、用途和选型条件 | 子产品、采购指南、询价入口 |
| 子产品页 | 说明工艺、几何、安装接口、尺寸和检验要求 | 所属系列、匹配指南、询价入口 |
| 指南与应用文章 | 回答一个具体采购或技术问题 | 对应系列或子产品、相关指南、询价入口 |

评估首页六张分类卡是否直接进入既有系列页，减少经过筛选目录的步骤；保留完整目录入口。检查所有内部 URL、锚点、孤立页面和 sitemap 目标，不只检查产品链接。

Product 结构化数据应与页面目的和可见事实一致，系列概览页单独审核。区分 JSON 合法、Schema.org 语义与 Google 富结果资格，不编造价格、库存、评价或认证来满足检查器。

### 第一轮内容主题

以下顺序依据现有资料成熟度提出；取得 GSC、实际询盘和供货优先级后调整，不代表已测得的搜索量或利润排名。

| 主题 | 既有入口 | 首批内容与实用资产 |
| --- | --- | --- |
| 剪板机刀片 | `/products/sb-001` | 替换刀片尺寸和孔位检查表；闸式与摆式适配核对，明确上下刀位置 |
| 分切刀 | `/products/sk-001` | 纸膜与金属箔的询价差异；切法、配刀、刀座和安装接口检查表 |
| 折弯模具 | `/products/pb-001` | 上下模及夹具接口识别；直刀与鹅颈刀的避让和具体载荷核对 |

滚剪刀与分切刀须按实际切法、材料和刀组安排区分，不能只依赖关键词或圆形外观。Nearblade 的折弯模具内容聚焦工具采购，如程的机床采购内容不直接搬用。

随后按证据和需求扩展轧钢刀、瓦楞纸切刀、刮墨刀、削片刀、粉碎刀及齿刀等主题。初期建议每周完成 2 篇有依据的新文章、2 至 3 个不同旧页面的实质优化；四周后评估。新文章与旧页面优化分别计数，不用改日期、缓存版本或重复修改同一页凑数。

首月候选题包括刀片替换尺寸清单、闸式与摆式刀片适配、纸膜与金属箔分切询价、分切刀刀座接口、折弯工具接口、直刀与鹅颈刀选择、询价检验要求及替换记录管理。先检查现有三篇文章的覆盖，适合扩充旧文的问题不另建重复页面。

## 每次执行流程

1. 阅读上次记录、当前工作区与观察队列，保留其他任务的改动。
2. 选定一个具体问题，记录数据依据或内容假设、目标 URL 和预期改善的采购环节。
3. 核对搜索意图与现有 URL；先研究是否需要新页面，再收集技术原始资料和可用图片。
4. 修改正文、相关入链与出链、元数据和匹配的结构化数据，同步九种语言包。
5. 运行相关检查及必需构建，对新页面和布局变化检查桌面与手机实际渲染。
6. 记录本地完成状态，按当时有效授权处理提交、推送和部署。
7. 获得发布授权并部署后，核对普通线上 URL、实际引用资源和版本，再进行适当的 sitemap 或 URL 检查操作。
8. 第 7 天检查抓取和技术状态，第 14、28 天观察查询及采购路径，低流量页面延长观察期。观察期内避免反复改写核心标题。

## 内容和图片验收

- 尽早回答具体问题，把适用条件和限制写在结论附近。
- 提供独立价值，例如尺寸检查表、选型表、工程示意或有依据的示例，不强制堆字数或每节添加数字。
- 技术数字注明来源、单位、产品与工况。区分计算示例、目录额定值和本站已确认能力。
- 不编造客户案例、工程签字、测试结论、作者身份或竞争对手承诺；竞品用于观察意图和内容缺口，技术事实优先采用原始资料。
- 产品图片及详情修改先遵循[产品图片工作流](product-imagery/WORKFLOW.md)，保留内部来源与版本记录，公开页面不加入制作说明。
- 文章应获得相关既有页面的入链，并链接到适配产品与询价入口。新增可见内容同步翻译，表格和结构化数据与正文一致。
- GEO 与正常内容验收合并：回答直接、条件清楚、实体一致、正文和表格可读取。不添加隐藏 AI 指令，不把 `llms.txt` 当作排名机制或收录保证。
- 日期只反映真实的发布和实质修改，不用自动刷新日期制造新鲜度。

## 验证和发布

用户已确认后续页面统一沿用完整 HTML 预渲染方式。新增或修改页面时，必须让初始 HTTP 响应直接包含主要正文、标题、可抓取内链和对应 SEO 元数据；不能只返回空应用容器，再依赖浏览器 JavaScript 生成主要内容。React hydration 用于接管交互。新增公开路由须纳入静态生成、SEO 配置、sitemap 及相应测试；验收时直接读取该 URL 的原始 HTML，并核对预览与线上响应。

`npm test` 会执行构建和测试；`git diff --check` 检查补丁格式。构建预览使用 `npm run preview`，开发服务器不能替代静态正文及初始元数据验收。自动化 DOM 交互测试不能替代桌面和手机视觉检查。

发布遵循[部署文档](DEPLOYMENT.md)，区分源码实现、测试通过、部署完成、线上验收和确认收录。Git 推送成功不等于线上版本更新；GSC 请求受理不等于已收录。

本工作流不新增定时任务、社交发布或持续自动部署授权。用户已在本轮明确授权提交并部署当前批次；后续批次按届时授权执行。外链工作可先整理相关资源、真实企业资料和外联草稿；发送消息、发布到平台及付费另按用户授权执行。

本批发布前复核新增了预览 HTTP 路由测试：Vite 默认会将无尾斜杠的产品地址回退到首页，导致产品页 hydration 不一致；`vite.config.ts` 的预览中间件现优先读取对应 `index.html`，与生产 Nginx 的路由查找一致。30 项测试全部通过。此前 29 项是修复前的历史结果。

## 转化和复盘

有统计能力时分别跟踪产品与指南访问、询价入口、邮件及 WhatsApp 点击。合格询盘以实际收到并核对的需求为准；不在分析记录中保存客户隐私资料。

每次记录日期、选题原因、数据范围、改动 URL、技术依据、测试和视觉结果、实现及发布状态、阻塞项和下次观察日期。没有转化统计时明确记录缺口，不把自然搜索点击当成询盘。

后续多语言 SEO 应依据目标市场和维护能力规划独立语言 URL、完整内容与 hreflang；现有客户端翻译不算九套已独立索引的页面。
