# 产品图片采集与详情页工作流

适用于 Nearblade 从公开供应商页面选择产品图片、完善详情并展示本地效果。先以剪板机刀片 `sb-001` 走通，再逐款扩展。用户已确认的页面方向是深蓝工业 Hero、清楚的银色刀片和统一白底轮播；页面不展示素材来源或制作过程。当前修改未提交、未发布。

折弯机上模与下模的分类扩充、豆包调研、既有页面复用和分批接入，另按 [折弯模具扩充工作流](../catalog/press-brake-expansion-workflow.md) 执行；图片质量和实际页面检查仍遵守本文件。

## 搜索与比较

1. 先读取产品名称、用途、现有规格和图纸要求，确认要找的是刀片而不是整机。区分金属剪切刀、切纸刀、摆式刀和闸式刀。
2. 在用户已登录的正式浏览器中搜索对应关键词，使用正常页面操作。不要建立反检测或绕过验证的流程。登录或验证需要用户操作时，保留当前页面。
3. 每款以五家不同店铺作为首轮比较目标，查看图库及详情，而不是只看搜索结果缩略图。候选不足时继续扩展。
4. 内部记录产品链接、店铺、原图地址、用途匹配程度和选择或淘汰原因。同一店铺的多个商品不能算多家店铺。

本轮比较了鑫尔利、华天、Alas、SKS 和欧维。鑫尔利旧图因尺寸不足且带标识被淘汰；SKS 候选图有明显品牌标识。无标识不等于拥有图片权利，也不证明图片未经修饰；使用状态和编辑情况应保留在内部记录中。

## 获取原图

优先打开页面公开的原尺寸图片链接，在正式浏览器里单独保存。只有图片单独保存不可用时，再尝试截图；截图不能算高清原图。需要读取公开原图地址时可使用浏览器查看页面源代码，但只提取必要的图片 URL，不输出账号信息、令牌或整页原始内容。

Chrome 的“网页，全部”可用于保存研究快照，但页面里的无关资源可能让下载长期卡在 97%。不要重复等待或把点击“保存”当作完成；改为单独保存原图，成功后取消自己启动的挂起任务。

检查下载记录和磁盘文件。Alibaba 图片 URL 的扩展名与实际编码可能不同，本轮以 `.png` 结尾的资源实际为 AVIF。按文件内容识别格式，使用正确扩展名。不要因 `sips` 不能读取某种编码就认定文件损坏。

## 清晰度与选图标准

| 检查项 | 处理标准 |
| --- | --- |
| 原生尺寸 | 正文图优先长边至少 1200 px；960 至 1199 px 仅在约 600 px 展示区通过视觉检查后使用。小图优先重新找图。 |
| Hero 尺寸 | 根据实际容器和裁切检查，不套用正文图门槛。优先横向原图；1920 px 以上原图更适合桌面全屏，仍需看原生细节。 |
| 实际清楚程度 | 放大检查刃口连续性、孔壁、轮廓、金属纹理、压缩块、重影与锐化光晕。大像素数不能掩盖模糊。 |
| 品牌与水印 | 检查四角、背景、刀身、孔边和宣传文字；优先原本无标识的图片。有标识的候选先继续找替代图，需要编辑时保留原始及编辑记录。 |
| 产品真实性 | 正确的用途和几何优先。对过度平滑、渲染感或明显修饰的图片作内部标记，不把供应商产品图直接认定为实拍。 |
| 角度搭配 | 选一张整体图，加不同角度的孔位或刃口图，避免三张几乎相同的照片。 |

可运行本地元数据检查工具：

```sh
node scripts/audit-product-photos.mjs path/to/image1 path/to/image2
```

该工具依赖 macOS `sips`，另支持本轮 AVIF 文件的尺寸读取。它输出尺寸、大小和哈希；`approved: false` 表示尚未人工审批，不会自动判断锐度、水印或真实性。生成工具要求的尺寸不等于输出尺寸；本轮实际输出为约 1254、1448 和 1672 px，不应宣称已经得到 3K 或 4K 图片。

## 图片处理与页面配色

按需要使用当前 imagegen 技能编辑，原图与每个候选版本均保留。编辑提示词只描述必要变化，逐张检查结果；不要因提示词写了“保持几何”就默认输出完全一致。

清晰度增强只在更高质量原图不足时使用。检查刀片数量、孔数与位置、长边直线、厚度、刃口和材料外观；新增的纹理和细节属于编辑结果，不能据此补充技术参数。透明抠图必须检查边缘白点、杂色、孔洞和光晕；有缺陷的输出不能直接接入页面。

Hero 和图库分别准备：

- **Hero**：以首页真实渲染效果和原背景图为色调参考，使用深蓝工业背景并保留明亮银色产品。使用 `PageHero` 的共用照片布局和遮罩，避免把白底方图硬套进透明产品图模式，也避免 multiply、低透明度和深遮罩三层叠加。先看背景图片本身，再调遮罩。
- **图库**：统一白底，图片内部四角和大面积底色也应为白色；只保留贴近产品的轻微自然阴影。展示区和缩略图同步保持白底，不能只修改外层 CSS。Hero 的深蓝版本不要加入白底轮播。

不把手册拼图当作同组产品照片。当前试点保留手册内部资料，但不在页面显示参考入口。其他产品的尺寸示意和检测要求属于客户需要的信息，不能误删为“素材来源提示”。

## 实际页面检查

1. 修改唯一目录 `content/catalog/products.json` 的主图、独立 `heroImage` 和图库数组（`src/data/products.ts` 负责类型与读取），核对分类卡片与分享图片是否也使用该主图。
2. 在实际产品页检查 Hero 全屏裁切、文字可读性、图片亮度、背景与首页的协调程度；不能只看图片文件或独立样例。
3. 点击全部缩略图，核对底色和产品大小，检查放大、关闭、键盘与手机布局。未实际检查的项目不能写成“通过”。
4. 新增或移除页面文字时同步九种语言包，不能只改英文或用英文填充其他语言。构建会校验键集合。
5. 运行 `npm run build` 和 `git diff --check`。检查 `dist/` 确认产品资源中没有内部来源 JSON。
6. 展示本地链接或截图，说明改动范围及验证结果。除非用户明确要求，否则不提交、不推送、不部署。

## 本轮错误与后续防范

| 本轮错误 | 后续必须采取的做法 |
| --- | --- |
| 只选一家，最初三张照片仍有品牌水印且只有 800 px 左右 | 多店比较，先审原图尺寸和标识，再制作样例。 |
| 把 URL 的 960 尺寸当成原图质量 | 检查磁盘文件或浏览器原图尺寸；本轮有主图原生只有 749 px。 |
| 整页下载卡住仍以“已保存”描述进展 | 下载完成与文件可读才算成功，及时切换单图下载。 |
| 同一 Hero 遮罩代码被误认为视觉已经一致 | 并排对照实际页面与原背景图，白底照片不能靠加深遮罩变成同样的工业背景。 |
| 乘色混合加重遮罩，产品暗到看不清 | 取消额外叠层，先准备正确色调的图片，再用共用组件。 |
| 轮播图白底、灰底、手册拼图混用 | 统一图片内背景与展示区，资料图不混入照片轮播。 |
| 增强图透明边缘出现白点和杂色 | 检查全尺寸输出，淘汰缺陷版本；不要直接上线。 |
| 制作记录放在 `public/`，页面还显示目录参考入口 | 内部记录与公开图片分开；检查正文、alt、公开 JSON 和 `dist/`。 |
| 生成结果与要求尺寸不同，仍容易被表述为高清恢复 | 记录实际尺寸，区分 AI 编辑与原始实拍证据。 |
| 工具结果输出了完整 base64 图片数据 | 图片用图像输出接口或本地查看，日志只保留路径和小量元数据。 |

## 2026-11-01 补充：图片类型与几何准入

选图时先验身份，再检查画质和排版。逐项辨认上模、下模或附件，工作刃或V槽、刀柄、承载肩、支承底座、端面及实际安装方向。多V逐槽核对数量、所在面和实体连接；不能把可调V、旋转V、双V混为一类。商品名、文件名、平放姿态和生成提示词均不能替代端面、图纸或对应实物证据。

Hero、图库、工程图及正文各自核对，再交叉比较；图库通过不代表 Hero 通过。工程示意只表达对应类型，不作为确定接口、角度或尺寸的供货图纸。生成图逐项检查几何，禁止用AI修图解决身份不明问题。

本次直身上模白底图只有平放视角，工作刃、刀柄及端面不足以确认与页面一致，因此撤下公开引用，保留原图和来源记录。当时未核实照片的页面临时改用相应工程示意；此为历史处理，介绍区规则已被下面的用户修订替代。撤图时同时检查列表、详情、缩略图、放大、结构化数据、分享图片和构建HTML，不能只换主展示图。

自动检查、资源加载检查和人工几何检查分别记录；构建通过不能算图片选型通过。浏览器短超时失败后刷新状态重试一次，仍失败则保留现场、记录缺口并继续独立工作，不能无期限等待或把尝试写成完成。

## 2026-11-01 用户修订：以鹅颈页作为介绍区标准

用户指出介绍页面的预览大图应使用网上核实的实物图，尺寸规格图放到下面，指定 `/products/pb-gooseneck-punch` 为标准。此要求优先于此前“缺图时把工程图移到介绍区”的临时方案。

- 接入时同时更新目录主图和 `images`，移除本批已补照片产品的 `mediaMode: specification`，复用鹅颈页现有照片布局及下方指南。保留既有URL和独立Hero。
- 照片与工程示意逐项核对槽数、所在面、工作刃和安装结构。双V不能用翻面槽示意去对应同面双槽照片；多V不能将三槽照片写成四槽或八槽标准配置。示意图仍不是供货图纸。

- 验收检查介绍区真实照片、下方尺寸图的DOM顺序、桌面/手机实际页面与放大。自动检查应防止本批页面退回顶部规格图模式；人工视觉检查另行记录。

## 产品页面制作标准（2026-11-01）

后续新增页面和补充已有页面都按本节执行。与本文早期试点或 README 历史说明不一致时，以本节及用户后续明确要求为准。页面布局参考 `/products/pb-gooseneck-punch`；分类依据仍是手册，不随参考页面或新照片变化。

### 1. 先核对手册、现页和产品身份

从 `product.docx` 对应章节同时读取文字和嵌入原图，不能只检索标题或根据图片文件名判断。若只有整理版 PDF，则核对对应页的文字和图示。记录用途、产品形态、子类、材料、工艺、安装接口及资料未能证明的项目。

读取 `content/catalog/products.json`、对应 `tooling-details.json` / `blade-details.json` 及既有页面。先列出中文名、英文名、同义词、现有 ID、URL 和所属系列。已有页面优先完善；新页面必须有独立工艺或产品身份依据，不能将材质、角度、适配设备或包装方式随意拆成型号。保留旧 ID / URL；必要归并按现有重定向机制处理，并更新测试和 SEO。

油墨刮刀的实例：手册展示多层卷料、盒装卷料和抽出短段；盒装是交付／展示形式，不是新一级分类。凹印、柔印是应用维度；标准、组合、蓝钢、不锈钢、陶瓷及组合刀架是手册列出的范围，不应相互替代。普通钢带照片不能证明蓝钢、不锈钢、陶瓷涂层或刃口规格，包装盒也不能当刀架。

### 2. 搜集并比较实际照片

先以五家不同供应商为比较目标，进入商品或制造商详情页检查产品和用途，再选原图。Alibaba 使用正式登录浏览器；供应商官网也可作为来源。记录哪些只读了页面／搜索缩略图，哪些确实下载并放大检查；同一供应商的不同网站不重复计数。低清图、品牌图或结构不符的候选写明淘汰原因。

把网页地址、原图地址、供应商、访问日期、格式、真实像素、文件哈希及使用状态记入内部记录。原图保存在被忽略的 `research/alibaba/<产品-日期>/`，即使来自其他官网也沿用现有研究目录；不可把账号快照或文档直接放入 `public/`。执行 `node scripts/audit-product-photos.mjs <图片路径>` 并人工看全图、局部及放大图。目标尺寸和不足时的处理沿用本文清晰度标准；AI 输出变大不能填补原图分辨率证据。

### 3. 按角色准备三类独立资源

| 角色 | 内容与处理 | 页面位置 |
| --- | --- | --- |
| 实物图库 | 对应类型的真实产品照片；必要时基于照片编辑白底。整体、包装／卷料和细节图互补，不把同一张换色图当不同产品 | 介绍区大图、缩略图及照片放大 |
| Hero | 独立深蓝工业背景，保持产品明亮及标题留白；使用共用 `PageHero`，不得为了配色牺牲产品几何 | 顶部全屏主图 |
| 尺寸与配合 | 对应产品工艺、工作部位和安装结构的工程示意；尺寸字母用于沟通，不能编成标准供货尺寸 | 介绍区以下的独立指南及规格放大 |

照片证据不足时先保留“待补图”的内部状态，不用生成新产品外形冒充已经核实的实物。临时例外如刀架 Hero 保留原照片及共用遮罩，要记录视觉差异和待完善项，不能将例外描述成全部满足深蓝背景标准。

### 4. 基于原照片编辑并逐项验形

需要处理时使用当次可用的 imagegen 技能和内置工具，先查看原图，再提交编辑；不可仅凭文字生成外形后称为实物照片。优先只改背景、留白、曝光或必要的第三方标识。原图不覆盖，最终文件使用含版本号的新名称。输出留在工具目录后，必须将被选中的文件复制／转换到项目内再引用。

可复用的提示词结构（按产品填具体内容，不机械照抄）：

```text
Use case: precise-object-edit
Asset type: product gallery photo / independent product Hero
Input: 已核实的原照片；写明数量、形态、视角和工作部位。
Change only: 图库改纯白背景；或 Hero 改深蓝背景并为标题留白。
Preserve: 产品数量、完整轮廓、厚薄比例、孔数孔距、刃口、V 槽、
          刀柄／接口、卷绕关系、盒体支柱和出料端等可见结构。
Avoid: 新增部件、重建未知几何、编造表面细节、品牌、参数和认证。
```

生成后与原图逐项对照，不以提示词中写了“保持不变”作为通过证据。刀片检查刃口、孔位和数量；折弯模具检查端面、V 槽数量及所在面；卷装刮刀检查卷绕和出料连续性；刀架检查紧固件数量及排列。改变结构的候选必须拒绝，必要时直接采用原照片。记录实际输出像素、格式、提示词、工具模式、修改范围、接受／淘汰原因和授权状态。处理后的纹理不能用于推导材料、尺寸或制造能力。

### 5. 接入唯一目录和共用页面

修改 `content/catalog/products.json`，不要另建一套目录或复制产品页 JSX。`image` 是主图，`images` 是白底实物轮播，`heroImage` 是独立 Hero；完整产品通常使用 `galleryFit: "contain"` 防止裁掉端面和出料端。补齐合格实物照片后移除该产品的 `mediaMode: "specification"`，尺寸图仍放在下方。系列子类使用 `variantGroups`，既有子页面入口使用 `productGroups` / `parentId`；复用 `ProductTypeGroups` 和 `ProductSeriesNavigation`。

每个产品 ID 在对应详情数据中明确用途、尺寸、设备适配和公差检验资料，不能继承不相关系列说明。新增页面同步 `content/seo/pages.json`，核对标题、描述、canonical、Product JSON-LD、分享图、列表和系列入口。不得添加供应商的交期、认证、硬度、销量或未经确认的尺寸承诺。

新增图库也可能新增动态缩略图 alt。运行 `npm run i18n:extract`，补齐 `content/locales/` 九种语言，再构建生成 `public/locales/`；不使用英文填充其他语言。公开文案、alt 和构建结果不加入来源店铺、提示词、本机路径或内部记录，也不编造“本厂未经编辑实拍”。

### 6. 实际页面验收与失败处理

运行 `npm run build`，在构建预览中逐页检查：Hero 裁切与文字、全部图库图片、缩略图切换、放大与关闭、下方尺寸指南、系列导航和询价入口。桌面和手机（例如 390×844）分别检查，确认无横向溢出、图片不裁断、文字可读。不能把共享组件或相同图片推断成每个页面已验收；自动、桌面、手机及放大结果分开记录，未检查明确写未检查。

浏览器超时后刷新状态并重试一次；仍失败就记录具体缺口并推进独立检查，不反复空等。下载未结束就不能记为原图已保存。用户正在操作同一浏览器时不要抢操作，保留待验收项。实际图片不符、生成改变结构或语言校验失败，先修正再发布，不以构建通过替代产品身份检查。

### 7. 内部交付记录与发布

每批记录保存在 `docs/product-imagery/`：需求、手册依据、受影响 ID、供应商比较、原图路径和像素、最终图片路径、提示词与修改范围、几何核对、权利状态、真实验收范围、照片缺口及提交／发布状态。可参考 [油墨刮刀照片记录](doctor-photo-based-2026-11-01.json) 和 [盒装卷料记录](doctor-box-photo-2026-11-01.json)。原始 Word 文档、网页快照和内部记录不进入站点静态产物。

交付前运行 `git diff --check`，检查引用和内部信息隔离；提交后按 [ECS 部署文档](../DEPLOYMENT.md) 执行 `npm run build:ecs`（包含完整测试）、预览、`npm run publish:ecs`。只有获得当次发布授权才推送发布分支；用户本次授权不自动扩展到未来任务。`main` 推送不触发部署，`push_remote` 才触发 ECS 同步。等待对应发布 commit 的 Actions 成功，再核对线上 HTML 的 JS/CSS 版本及新图片内容哈希；推送成功不等于网站已更新。

完成标准：产品身份有依据、旧页面不冲突、白底照片在上、尺寸图在下、九种语言完整、实际页面验收有记录、构建测试通过；已授权发布的任务还必须确认线上版本。交付说明列出本地／线上链接、已完成项和仍存在的原图或型号证据缺口。
